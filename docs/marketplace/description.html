Review your own git changes in the IDE before you push them for team review. Pick two comparison points, read the diff, annotate it, track what you have covered, and export your findings for colleagues or AI coding agents.

It is built for the pull request that does not exist yet: a feature branch, often written with the help of an AI assistant, that you want to go through carefully on your own machine first.

What you can do

  • Compare any two points: branches, tags or commits. The default is pull request style, diffing from the merge base. Commits are pinned, so the review does not shift while the branch moves.
  • See the whole change: a file tree with added, modified, deleted and renamed files, and the IDE's own diff viewer (side by side or unified) for the content.
  • Annotate code: add change requests, questions or notes to a line, a selected range (in a unified diff, one range per side), a file or the whole review. Reply, resolve, reopen, edit or delete them; deleted comments are kept and can be restored.
  • Track progress: mark files and individual hunks as reviewed. A mark follows its lines when the file changes and shows as stale where they changed; the tree shows progress by changed lines and which files changed since you viewed them.
  • Pick up where you left off: reviews are saved the moment you save a comment and reopen automatically after a restart or crash.
  • Follow a moving branch: Update Review pins the new commits. Each comment is checked against the new code; one whose lines moved or changed is marked outdated with a suggested new place that you can accept, instead of being lost or silently moved.
  • Hand over your findings: export a Markdown report, a machine-readable JSON file, and a ready-to-paste prompt for an AI agent. Copy a single comment as a prompt. Reply to comments, and mark a review done or archived.
  • Improve your agent rules: mark a comment as a recurring pattern and get a proposed update to AGENTS.md that you can edit before it is written. Comments flagged without rule text are listed as needing wording.

Where your reviews are stored

Reviews are stored in review groups. A group is one git repository holding the reviews of as many projects as you like; each review is a small file plus one append-only log of events per device, in a documented format, so merging two devices never conflicts and other tools can read the same reviews. Give a group a remote to keep it in sync between your devices, with a separate SSH key per group if your accounts need different identities. Use separate groups to keep unrelated work, such as different organisations, apart. Nothing is stored in your project's repository. Reviews made with version 0.1.0 are imported automatically.

Requirements

  • An IntelliJ-based IDE, version 2026.2 or newer, with the bundled Git plugin enabled.
  • A git executable (the one configured in the IDE is used).

Privacy

The plugin collects no telemetry and makes no network connections of its own. The only network traffic is git talking to a remote that you configured for a review group. Review data is written to the folder you choose (default ~/.local-review).
